## 详细说明（每个坑按 现象 → 原因 → 解决 → 怎么验证 展开）

### 1. 上传失败 / 一直卡在 "Connecting..."

- **现象**：点上传后永远停在 `Connecting........_____.....`，最后报错 `A fatal error occurred: Failed to connect to ESP32-S3`。
- **原因**：芯片没进下载模式，或根本没连上电脑。常见子原因：①芯片处于普通启动模式且板载转串口没触发复位时序（某些线/某些电脑上会这样）；②USB 线只充电不传数据；③串口监视器开着占用端口；④开发板型号/端口没选对。
- **解决**：按顺序来——①**按住 BOOT 键不松，点上传，看到 "Connecting..." 时松手**（官方规定的强制下载模式操作：按住 Boot 再按 Reset）；②换一根能传数据的 USB 线；③关掉串口监视器再传；④确认板型是 ESP32S3 Dev Module、端口选的是板边 USB-to-UART 口对应的 COM。
- **怎么验证修好了**：上传进度条走到 100%，提示"Leaving... Hard resetting"，串口监视器里能输出程序打印的内容。

### 2. 上电瞬间 LED 闪一下 / 引脚乱跳 / 程序偶尔起不来

- **现象**：每次上电外接 LED 都会莫名其妙闪一下；继电器偶尔上电就动作；有时复位后程序没运行。
- **原因**：用了启动配置脚（strapping pins）——官方数据手册明确 GPIO0、GPIO3、GPIO45、GPIO46 这 4 个脚上电瞬间会输出特殊电平来决定启动方式，接在上面的负载会被这个瞬间电平驱动。
- **解决**：项目里**避开 GPIO0/3/45/46**，用普通引脚（如 GPIO4、GPIO5、GPIO6、GPIO7、GPIO8 等）；GPIO0 同时是 BOOT 键所在脚，更不要接负载。
- **怎么验证修好了**：把 LED 换到普通引脚后，反复断电上电 10 次，LED 一次都不闪，程序每次都正常启动。

### 3. 5V 信号直接怼 GPIO / 模拟口读数异常或烧脚

- **现象**：接了 5V 输出的传感器（如 HC-SR04 超声波）后读数全是错的，严重时引脚发烫、芯片冒烟。
- **原因**：ESP32-S3 是 **3.3V 逻辑**，ADC 量程只有 0-3.3V。5V 信号直接输入超出引脚耐受，损坏 GPIO/ADC。
- **解决**：信号线经**电阻分压**（如 1kΩ 与 2kΩ 串联，5V 分压到约 3.3V，中间抽头接 GPIO）或加**电平转换模块**；更简单的是优先选 3.3V 供电的传感器模块（DHT22 支持 3.3-5V，可直接接）。
- **怎么验证修好了**：用万用表量 GPIO 引脚电压，信号高电平时读数 ≤3.3V；ADC 读数恢复正常，传感器数据正确。

### 4. 开 WiFi 后反复重启 / 一连接网络就复位

- **现象**：程序一开 WiFi 就重启循环，不开 WiFi 一切正常；插着 USB 也偶尔黑屏重启。
- **原因**：WiFi 发射瞬间电流峰值很大，USB 口供电能力不足（尤其用充电线、USB 集线器或笔记本 USB 口）会把 3.3V 电压拉垮触发欠压复位。
- **解决**：用**好一点的 5V 电源**从 5V+G 引脚直接供电（官方允许的供电方式，注意 GND 共地）；减少外设电流；不要用劣质 USB 集线器。
- **怎么验证修好了**：接上独立 5V 电源后，反复开关 WiFi、持续传输数据 5 分钟，不再复位；串口监视器不再打印 boot 信息。

### 5. 串口监视器乱码 / 看不到输出

- **现象**：串口监视器全是 `�` 乱码，或什么也不显示。
- **原因**：波特率不匹配。ESP32 的 Arduino 串口默认 115200（你的代码里 `Serial.begin(115200)` 写了多少，监视器右下角就要选多少）；选成 9600 就会乱码。另外一个坑：**代码没写 `Serial.begin()`** 当然没有输出。
- **解决**：监视器右下角波特率选 **115200**；确认代码里有 `Serial.begin(115200)`；监视器没反应就按一下板上的 RESET 键。
- **怎么验证修好了**：重新打开监视器后看到正常中文/英文输出，无乱码。
