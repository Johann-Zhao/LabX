## 详细说明

### 1. 设备管理器看不到 COM 口 / CH340 显示感叹号
**现象**：USB 线插上学习板，电脑毫无反应，设备管理器"端口"分类下没有 COM 口（或"其他设备"里有个黄色感叹号的 USB-SERIAL）。
**原因**：CH340（或 CP2102，看板子芯片丝印）驱动没装或没装对。驱动是电脑识别串口的前提，没有它 STC-ISP 找不到端口，什么都下载不了。
**解决**：装对应芯片的官方驱动（搜"CH340 驱动"下载，网上大量教程配套驱动包可用）；换一个 USB 口插、换一根**能传数据**的线（很多线只能充电）；插上后去设备管理器右键"扫描检测硬件改动"。
**怎么验证修好了**：设备管理器"端口（COM 和 LPT）"下出现 `USB-SERIAL CH340 (COMx)`，且无感叹号。此时打开 STC-ISP 的串口号下拉框能看到这个 COM 口。

### 2. 下载卡在"正在检测目标单片机"，怎么都不动
**现象**：STC-ISP 点"下载/编程"后一直提示"正在检测目标单片机"，进度条不走。
**原因**：STC 单片机靠**冷启动**进入下载模式——软件就绪后，单片机必须在**断电状态重新上电**才会响应握手。没做这一步，单片机还在跑旧程序，不理会电脑。
**解决**：顺序很重要：先点"下载/编程" → 看到"正在检测" → **立刻给板子断电再上电**（关电源开关再开，或拔 USB 再插）。如果还不行，依次检查：COM 口是否选对、串口监视器/串口助手是否占用着端口（关掉）、单片机型号是否选了 STC89C52RC。
**怎么验证修好了**：断电上电后提示变成"握手成功"，进度条走到 100%，出现"操作成功"字样。

### 3. 串口收发乱码（发给电脑的是乱码）
**现象**：单片机通过串口发数据，串口助手收到一堆乱码；或波特率设 9600 却发得驴唇不对马嘴。
**原因**：两边波特率不一致，或晶振频率不是串口常用的 11.0592MHz。8051 的串口波特率由晶振分频而来，晶振不是 11.0592MHz 的整数关系时（比如 12MHz），标准波特率会产生误差，累积成乱码。
**解决**：确认学习板晶振频率（看板子丝印，经典教学板多为 11.0592MHz），把串口助手波特率设成和代码里 `TMOD/TH1` 计算值一致（初学直接照抄教程例程的配置，别自己发明）；两边波特率必须相同。代码里如果用 `PCON = 0x80`（波特率加倍），9600 实际对应的是 4800，这也是常见坑。
**怎么验证修好了**：串口助手收到 `Hello` 之类可读字符，不再有"锟斤拷"或随机符号。

### 4. 程序下载成功，但 LED 不亮 / 一亮就不亮 / 亮度很暗
**现象**：烧录显示成功，板子上的 LED 却没有任何反应，或亮度明显偏低。
**原因**：三种常见情况——(a) 代码里引脚写错（板载 LED 实际在 P1 口，你写成了 P2^0）；(b) LED 是**低电平点亮**，代码却写 `LED = 1`；(c) 用的是 **P0 口**——P0 是开漏输出，没有内部上拉，直接驱动 LED 会拉不动（暗/不亮），必须外接上拉电阻。
**解决**：先看板子丝印/原理图确认 LED 接在哪个口、是高电平还是低电平点亮；把 `sbit LED = P2^0` 和 `LED = 0/1` 改成对应关系。用 P0 口时在引脚和 VCC 之间接 10kΩ 上拉电阻（或直接换用 P1/P2 口）。
**怎么验证修好了**：改完重新编译下载，LED 按预期节奏亮灭；用 `P0 = 0x00` 全低电平看 8 个灯是否都亮。

### 5. 数码管显示乱码 / 闪烁严重（进阶坑）
**现象**：静态数码管显示不对，动态数码管亮度忽明忽暗甚至数字重影。
**原因**：段码表写错（共阴共阳搞反），或动态扫描的消隐、延时节奏没处理好（扫描太快眼睛看到残影，太慢看到闪烁）。
**解决**：先确认数码管是共阴还是共阳（看板子原理图），段码表高低电平反过来；动态扫描每个位停留 1~5ms 且位选切换时先消隐再送段码。
**怎么验证修好了**：单个数字显示稳定无残影；多位数码管数字清晰、无重影、无明显闪烁。
